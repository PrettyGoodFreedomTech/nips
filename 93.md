NIP-93
=====
decentralized lists
-----

`draft` `optional`

This NIP defines lists of things that users can create and that anyone can add to. It provides an alternative to NIP-51 for list formation. The distinction is that for any given NIP-51 list, the list author has full control over list items, whereas for this NIP, list items are contributed by the community.

We introduce two event kinds: `9999` and `39999`, either of which can be used for declaration of a new list or for declaration of an item to a list. Whether to use kind `9999` or kind `39999` depends on whether the declaration author wishes the list or list item to be editable (kind `39999`) or not (kind `9999`).

## List curation and spam prevention

 _This NIP is agnostic regarding the choice of method or methods for list curation and spam prevention_. For example, a _personalized trust metric_ could be used to exclude items based on the personalized trust metric of the item contributor. The purposes of such methods may include:
- which items should be accepted to a given list
- which items should be excluded from a given list
- stratification of accepted items, if desired

A wide variety of methods of varying degrees of sophistication can be imagined. For simplicity, this NIP presumes them to be specified elsewhere. 

## Declarations of lists and list items

There are two actions: declaration of a new list, and declaration of a specific item that belongs to a given list. We use kind `9999` (or `39999`) for each of these actions.

### Tags

The `z` tag is required by all kind `9999` and `39999` events. It defines the category or categories to which the event belongs.
- When declaring a list, include the tag: `["z", "list"]`.
- When declaring a list item, include the tag: `["z", "<list_event_id>"]`, where `<list_event_id>` refers to the list declaration event of which this is an item. Alternatively, `<list_event_id>` can be replaced with a human readable name of the list, e.g. one may use a `z` tag of `country` rather than an event id when adding `Switzerland` to the list of countries.

Technically, the only requirement for the `z` tag is that it must be a string. If an item belongs to multiple lists, there will be one `z` tag for each list to which it belongs.

The `p`, `e`, `t`, and `a` tags are used in list item declarations when declaring a pubkey, event id, string, or naddr as an item on a list. The parent list declaration event `should` specify which of these tags are expected to be present in their children using the `required`, `allowed`, `recommended` and/or `disallowed` tags.

### List declaration

Declaration of a new list is a kind `9999` (or `39999`) event with `list` as the `z` tag.

It `must` have the `names` tag. The `names` tag must be followed by two strings: a singular form ("widget") and a plural form ("widgets"), as in the examples below.

Optional tags: `titles`, `slugs`, which also must have a singular form and a plural form, as is the case for the `names` tag.

It `should` make use of `required` or `allowed` tags to indicate which child item types are expected. For example: `["required", "p"]` indicates that child item declarations must make use of the `p` tag.

### Item declaration 

Declaration of an item on an existing list is a kind `9999` (or `39999`) event with the `z` tag indicating the event id of the parent list. It `should` have a `p`, `e`, `t`, or `a` tag, if indicated as `required` by the parent list declaration.

Optional tags: `name`, `title`, `slug`, `description`, `comments`. Each of these tags is followed by a single string element, as in the examples below.

A single kind `9999` or `39999` event can be used to declare multiple items, each with its own tag. However, it is recommended to use a distinct event for each individual item.

## Examples

### Example 1: a list of nostr developers

List creation:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "nostr developer", "nostr developers"],
    ["description", "This is a list of developers who build within the nostr ecosystem"],
    ["required", "p", "name"]
  ],
  "id": "<id_list_of_developers>"
}
```

Add a pubkey as an item on the list of developers:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "<id_list_of_developers>"],
    ["name", "Derek Ross"],
    ["p", "3f770d65d3a764a9c5cb503ae123e62ec7598ad035d836e2a810f3877a745b24"]
  ]
}
```

### Example 2: a list of long form articles on hyperinflation:

List creation:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "long form article on hyperinflation", "long form articles on hyperinflation"],
    ["description", "This is a list of long form content events on the topic of hyperinflation"],
    ["required", "a"],
    ["recommended", "title"]
  ],
  "id": "<id_hyperinflation>"
}
```

Add an naddr address as an item to the above list:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "<id_hyperinflation>"],
    ["a", "naddr1qvzqqqr4gupzq4rqjpyzsnf2z5wgma397sxr382z8mg90l80jf7m3z2k628z9wsrqythwumn8ghj7cnfw33k76twv4ezuum0vd5kzmp0qythwumn8ghj7ct5d3shxtnwdaehgu3wd3skuep0qq3kv6tpwskkxatjwfjkucme946xsefdwd5kcetwwskhg6tdv5khg6rfv4nqnxv6fx"],
    ["title", "Fiat Currency: The Silent Time Thief"]
  ]
}
```

### Example 3: a list of dog names:

List creation:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "dog name", "dog names"],
    ["description", "This is a list of dog names"],
    ["required", "t"]
  ],
  "id": "<id_dog_names>"
}
```

Add a piece of text as an item to the above list:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "<id_dog_names>"],
    ["t", "Fido"]
  ]
}
```

### Example 4: A single item on multiple lists

Create a list of dogs and a list of animals:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "dog", "dogs"],
    ["description", "This is a list (by name) of individual dogs"],
    ["required", "t"]
  ],
  "id": "<id_dogs>"
}
```

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "animal", "animals"],
    ["description", "This is a list of animals"],
    ["required", "t"]
  ],
  "id": "<id_animals>"
}
```

Now add Fido to both of the above lists.

```json
{
  "kind": 9999,
  "tags": [
    ["z", "<id_dogs>"],
    ["z", "<id_animals>"],
    ["t", "Fido"]
  ]
}
```

An alternate and equivalent way to add Fido to these two lists is to provide each list `name` (singular) in place of the list id:

```json
{
  "kind": 9999,
  "tags": [
    ["z", "dog"],
    ["z", "animal"],
    ["t", "Fido"]
  ]
}
```

The above can be translated: "Fido is a dog" and "Fido is an animal".

However, it is encouraged to use the list id if an appropriate one is known and available.

### Example 5: Declaration of the list of all lists

Declare a list of all known lists

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "list", "lists"],
    ["description", "This is a list of all the lists that exist within any given datastore"],
    ["required", "names"]
  ],
  "id": "<id_lists>"
}
```

Technically speaking, `["z", "list"]` could be replaced by  `["z", <id_lists>]`, but this is not necessarily recommended.

### Example 6: A list of lists of long form articles

Create a list of the lists of long form articles

```json
{
  "kind": 9999,
  "tags": [
    ["z", "list"],
    ["names", "list of long form articles", "lists of long form articles"],
    ["description", "This is a list of lists of long form articles"],
    ["required", "e"]
  ],
  "id": "<id_list_of_articles>"
}
```

Now add an item to the above list. Note that it points to the event above, from Example 2. 

```json
{
  "kind": 9999,
  "tags": [
    ["z", "<id_list_of_articles>"],
    ["e", "<id_hyperinflation>"],
  ],
}
```

## Retrieval

Retrieval of all lists:

```json
{
  "since": 0,
  "kinds": [9999, 39999],
  "#z": ["list", "<id_lists>"]
}
```

Retrieval of all items on the list of dogs:

```json
{
  "since": 0,
  "kinds": [9999, 39999],
  "#z": ["dog", "<id_dogs>"]
}
```
